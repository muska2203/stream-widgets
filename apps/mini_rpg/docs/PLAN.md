# Мини-RPG — PLAN

План последовательной реализации. Правила игры — `DESIGN.md`, целевая
архитектура — `DEVELOPMENT.md`. Общие правила репо — корневой `AGENTS.md`
(запуск через `py`, тесты `py -m unittest discover` зелёные до и после,
агент не запускает UI-приложения сам).

## Как работать с планом (для агентов)

- Задачи выполняются строго в порядке нумерации — каждая опирается на
  предыдущие. Не начинать задачу, если предыдущие не `[x]`.
- Статусы: `[ ]` — не начата, `[~]` — в работе, `[x]` — готова.
- Начиная задачу, ставь `[~]` и дату. Закончив — `[x]`, дату и одну строку
  «факт»: что реально сделано и отклонения от описания (если были).
- Перед сдачей задачи: `py -m unittest discover` зелёный; если задача
  добавляет CLI — прогнать его.
- Если реальность разошлась с DESIGN.md/DEVELOPMENT.md — сначала поправь
  документ, потом код (или зафиксируй отклонение в строке «факт»).
- Пользовательские проверки (браузер/OBS, живой чат) агент не выполняет —
  помечает задачу как «ждёт пользователя» в строке «факт».

## Этап 2. Модель героя

### [x] 2.1 `core/hero.py` (2026-09-30)

- `Hero`: статы (сила/ловкость/интеллект/выносливость/удача), уровень,
  опыт, золото, HP/мана, 3 слота (melee/ranged/armor). Чистый Python,
  rng инжектируется.
- Формулы (DESIGN.md): `max_hp = base_hp + 5×ВЫН`, `max_mana = 5×ИНТ`,
  `crit_chance = 2%×УДА`, урон = бросок N..M оружия + стата, крит ×2 от
  итогового урона.
- `equip(item)`: замена в слоте, старый теряется.
- `gain_xp(n)`: порог `10×уровень`, вычитание порога, мульти-ап за один
  килл; возвращает число апнутых уровней (игра покажет окна прокачки).
- `level_up(stat)`: +1 к стате; при ВЫН +5 и к текущему HP.
- `use_ranged()`: −1 use, при 0 — удалить из слота.

Факт: `Hero` (dataclass, статы/уровень/опыт/золото/HP/мана/3 слота) +
`new_hero(base_hp)` со стартовыми «Кулаками» 1–2; формулы константами
(HP_PER_ENDURANCE, MANA_PER_INTELLECT, CRIT_PER_LUCK=0.02, крит ×2,
XP_PER_LEVEL=10); rng передаётся аргументом в `roll_damage(slot, rng)` →
(damage, crit); `equip`/`gain_xp` (мульти-ап, возвращает число апов)/
`level_up` (ВЫН +5 и к текущему HP)/`use_ranged` (слот пустеет при 0).

## Этап 3. Бой

### [x] 3.1 `core/combat.py` (2026-09-30)

- `Combat(hero, mob, rng, level_scale)`: автомат одного боя.
  Ходы чередуются, первый — герой. Направления: голова/тело/ноги.
- Ход героя: вход — (оружие, направление); моб тайно (rng) выбирает блок;
  совпадение → 0 урона; иначе урон оружия + стата ± крит. Атака дальним
  тратит use всегда, даже при блоке.
- Ход моба: вход — направление защиты от чата (или None при пропуске);
  моб rng выбирает атаку; совпадение → 0; иначе урон моба − броня (мин 0).
- Скейлинг моба при создании: hp/урон/награды ×(1 + 0.15×(уровень−1)),
  округление к int (правило зафиксировать в DEVELOPMENT.md).
- Итог боя: победа → (xp, gold); смерть героя → проигрыш. Результат каждого
  хода возвращается структурой (кто, куда, блок/урон/крит) для оверлея.

Факт: `Combat(hero, mob, rng, level_scale=0.15)` с методами
`hero_turn(weapon, direction)` / `hero_skip()` / `mob_turn(defense|None)` →
`TurnResult(actor, weapon, direction, blocked, damage, crit, target_hp)`;
`rewards` → scaled (xp, gold) при победе, иначе None; `finished`/`hero_won`;
цикл и время не крутит (это game.py). Скейлинг `scale_mob()` ×(1+0.15×(ур−1)),
округление `int(x·k + 0.5)` — зафиксировано в DEVELOPMENT.md. Направления —
англ. константы `DIRECTIONS = ("head", "body", "legs")` (маппинг цифр —
этап 4).

### [x] 3.2 Тесты `tests/test_combat.py` (2026-09-30)

Факт: 20 тестов, все зелёные; направление блока/атаки моба подглядывается

## Этап 5. Игровой автомат (v1: только мобы)

### [x] 5.1 `game.py` (2026-09-30)

- `Game(cfg, ...)`: состояния RUN_START / EVENT / COMBAT / LEVELUP /
  GAME_OVER / ERROR (пустой пул), `update(dt)`, единая точка входа
  `handle_chat_message(user, text)`. Чистый Python, тайминг через dt,
  как в истории.
- EVENT: 3 двери (повторы мобов допустимы при пуле < 3), голосование
  `event_duration`; нет голосов — перезапуск с тем же составом; пул
  перечитывается при каждом входе в EVENT.
- COMBAT: чередование голосований атака/защита (`combat_duration`), после
  каждого хода показ итога `combat_outcome_pause`; нет голосов — пропуск
  хода. Конец боя: победа → награда → LEVELUP (по числу апов, по одному
  окну на уровень) → `combat_end_pause` → EVENT; смерть → GAME_OVER.
- LEVELUP: `levelup_duration`, нет голосов — перезапуск.
- GAME_OVER: итоги забега (уровень, убито, золото), `gameover_pause`,
  новый RUN_START.
- `VoteLoop` на каждую фазу со своим валидатором; таймеры — по правилам
  DEVELOPMENT.md (грабля с коллбэком, обнуляющим vote_loop).

Факт: `Game(cfg, ui=None, mobs_dir=...)` — состояния RUN_START (транзитное)
/EVENT/COMBAT (подфазы attack/defense/outcome/end) /LEVELUP/GAME_OVER/ERROR;
все правила «нет голосов» (двери/прокачка — перезапуск с тем же составом,
бой — пропуск хода), награды/счётчики забега (kills, gold_earned),
run_summary на GAME_OVER, автоматический новый забег. Таймер фазы —
`time_left` в Game, раунд закрывается явным `finish()`; VoteLoop после
finish() не трогается. Шов оверлея — `NullUI` (show_event/show_combat/
show_combat_outcome/show_levelup/show_gameover/show_error/update_votes),
под реальный WebUI этапа 6. Магазина/отдыха нет (этап 9), items_dir пока
не принимается; Item из пула с героем не шарится — моб копируется в
scale_mob, экипировки из пула в v1 нет.

## Этап 8. Точка входа

### [x] 8.1 `main.py` + `__main__.py` (2026-09-30)

- Конфиг → чат (Twitch/Mock по `mock_chat`) → `Game` + `OverlayServer` →
  цикл на `time.monotonic`; `--smoke` — авто-выход через 20 с; при старте
  печать адреса оверлея.
- Проверка: тесты зелёные; дальше задача ждёт пользователя — прогон
  `py -m apps.mini_rpg` с mock_chat, браузер, OBS поверх камеры.

Факт: порядок как в истории: `load_config()` → `Game(cfg)` → `WebUI(game)`
→ `game.ui = ui` → чат (`MockChat` при `cfg.mock_chat`/`--mock`/`--smoke`,
иначе `TwitchChat` на `cfg.channel`) → `OverlayServer(ui, cfg.overlay_port)`
→ цикл `time.monotonic` ~60 Гц (`chat.update(dt)` + `game.update(dt)`),
KeyboardInterrupt гасится, `server.stop()` в finally. Отклонения: чат живёт
в main.py, а не в Game (у истории внутри Game); rng мок-чата отдельный

### [x] 9.1 `game.py`: состояния SHOP и REST (2026-09-30)

- Двери набираются из смешанного пула (мобы + магазин + отдых); типы могут

- SHOP: до 9 случайных разных предметов, фильтр цены > золота, `0` —

Факт: состояния SHOP/REST, `Game(..., items_dir=DEFAULT_ITEMS_DIR)` — оба
пула перечитываются на каждом EVENT (битый предмет — экран ошибки, пустой
пул предметов — не ошибка: магазин просто не выпадает на дверях). Дверь —
`Door(kind, mob)` в game.py с иконкой/именем типа (🏪 Магазин, 🛏️ Зона

# Мини-RPG — DESIGN

Зрители чата Twitch коллективно ведут одного героя через бесконечный забег:
выбирают события-двери, качают характеристики и покупают снаряжение; бои с
мобами идут **автоматически**, а чат может вступить в отряд героя и бить
моба рядом с ним. Оверлей — локальная веб-страница
(`http://127.0.0.1:<overlay_port>`, адрес печатается при запуске), которую
стример добавляет в OBS источником «Браузер» (Browser Source);
прозрачность нативная, хромакей не нужен.

Аватарка героя на оверлее — пустая прозрачная рамка: стример кладёт под
оверлей источник с камерой, и его лицо оказывается «лицом» героя. Игра сама
камеру не захватывает и ничего в рамку не рисует.

Статус: реализовано (см. DEVELOPMENT.md). Все числа баланса ниже —
стартовые дефолты, крутятся в конфиге и контентных файлах.

## Цикл игры

```
RUN_START → EVENT → (COMBAT | SHOP | REST | ...) → EVENT → ...
                                              ↘ GAME_OVER → EVENT (возрождение)
```

- **RUN_START** — создаётся новый герой 1 уровня со стартовым набором
  (см. «Герой»); только самый первый старт без сейва.
- **EVENT** — на экране 3 двери со случайными событиями (мобы, магазин,
  зона отдыха — правило набора в «Типы событий»), чат голосует словом
  варианта (`event_duration` сек, см. «Режимы голосования»). Победившая
  дверь открывается, событие запускается. Дверь показывает иконку и
  название события (у моба — его иконка и имя, у магазина/отдыха — свои).
  Пустой пул мобов — экран ошибки (как в истории).
- **GAME_OVER** — герой умер: экран с итогами забега (убито мобов,
  заработано золота, список поверженных по боевым кличкам — сняты до
  сброса), пауза
  `gameover_pause` сек, затем забег продолжается тем же героем. Штраф за
  смерть: теряются золото и опыт, накопленный на текущем уровне, а
  статистика забега (убито мобов, заработано золота, поверженные)
  обнуляется; уровень, статы, снаряжение и общий счётчик смертей
  сохраняются, герой возрождается с полными HP/маной. Рестарт
  автоматический, стриму ничего делать не нужно.

Переголосование разрешено, при ничьей победитель случаен среди лидеров
(правило streamkit). Лидеры подсвечиваются все сразу; при ничьей по
окончании голосования игра держит фазу на `tie_resolve_pause` секунд
(~3 с) — на оверлее играет «рулетка»: пункты-лидеры по очереди моргают с
затуханием темпа, остановка на выпавшем победителе, затем исход
применяется.

**Нет голосов — овертайм, затем случайный выбор** (единое правило для
всех голосований — двери, магазин, прокачка; в бою голосований нет):

1. Раунд закончился без единого голоса → **овертайм**: то же голосование
   продолжается ещё `overtime_duration` секунд (дефолт 5). Слова вариантов
   и состав НЕ меняются — зрители голосуют теми же словами. Таймер на
   оверлее мигает и подрагивает, привлекая внимание. Овертайм бывает один
   раз на голосование.
2. Появился хотя бы один голос → обычное завершение (победитель или
   ничья с рулеткой среди лидеров).
3. После овертайма голосов всё ещё нет → **случайный выбор среди ВСЕХ
   вариантов** той же рулеткой, что при ничьей: фаза держится на
   `tie_resolve_pause`, оверлей перебирает все пункты и останавливается
   на выпавшем. Игра никогда не встаёт в ожидании голосов.

## Сохранение прогресса

Прогресс забега переживает перезапуск приложения: в живом режиме игра
пишет чекпоинт в `savegame.json` (рядом с пакетом, gitignored) и при
старте восстанавливается из него.

- Сохраняются только долгоживущие данные: герой (статы, уровень, опыт,
  золото, HP/мана, снаряжение) и счётчики забега (убито мобов, заработано
  золота, смертей, список поверженных, отложенные прокачки). Состояние
  автомата — фаза, бой, голоса, таймеры — не сохраняется никогда.
- Чекпоинт пишется на границах фаз: при входе в EVENT (все изменения
  героя к этому моменту уже отыграны) и при смерти героя — сразу после
  применения штрафа (золото и опыт текущего уровня обнулены, статистика
  забега сброшена, герой возрождён с полными HP/маной), прогресс не
  теряется.
- Восстановление — всегда свежим событием: герой и счётчики поднимаются
  из файла, двери бросаются заново; незавершённый бой/магазин переигрывается.
- Битый или устаревший файл не роняет стрим: он переименовывается в
  `savegame.json.bak`, и начинается новый забег.
- В мок/smoke-режиме сейв не пишется и не читается (как база чаттеров).

## Режимы голосования

Режим переключается настройкой `vote_mode` в `config.toml`:
`"words"` (дефолт) или `"classic"`. В обоих режимах внутри игры голос
остаётся каноническим ключом-цифрой, команда в чате — алиас ключа:
маппинг строит `Game` (`streamkit.VoteWords` для слов, статические
таблицы `core/choices.py` для классики); подсчёт, переголосование,
овертайм, ничья и рулетка работают одинаково. Оверлей в обоих режимах
показывает алиас на «клавише» варианта. Регистр и пробелы при вводе не
важны. Голосования — только двери, магазин и прокачка; бой голосований
не имеет (см. «Бой»), команда вступления в отряд — фиксированная в обоих
режимах.

### "words" (дефолт) — случайные слова раунда

Голосуют не цифрами, а короткими русскими словами: на каждое голосование
каждый вариант получает случайное слово из кураторского пула
(`streamkit/votewords.toml`, существительные 3–7 букв, без ё, без
омонимов). Цифры как ввод не принимаются.
Слова уникальны внутри раунда и не выдаются повторно в течение ~60 секунд
— защита от 30-секундного блока одинаковых сообщений у Twitch. Овертайм
(нет голосов) слова не перевыдаёт — голосование продолжается теми же;
новые слова раздаются только новому голосованию.

### "classic" — фиксированные команды

Осмысленные команды, постоянные между раундами (зритель учит их один
раз), таблицы в `core/choices.py`:

| Голосование | Команды |
|---|---|
| Двери (слева направо) | `левая` · `средняя` · `правая` |
| Прокачка | `сила` · `ловкость` · `интеллект` · `выносливость` · `удача` |
| Магазин | `1`..`N` — купить товар · `выход` — выйти |

В classic-режиме случайный пул слов не используется (`VoteWords` не
создаётся).

## Герой

Характеристики (нарочито тупые, одна характеристика = один эффект):

| Стата | Эффект |
|-------|--------|
| Сила | + урон оружием |
| Ловкость | − кулдаун атаки героя |
| Интеллект | + мана (тратить пока нечем — задел под способности) |
| Выносливость | + максимум HP |
| Удача | + шанс крита |

Старт: все статы 0, уровень 1, золото 0, HP = `base_hp` (20) + 5×ВЫН,
мана = 5×ИНТ. Кулдаун атаки героя: `hero_cooldown` −
`agility_cd_reduction`×ЛОВ (дефолт 5.0 − 0.5 с за очко), не ниже
`min_cooldown` (1.0 с) — уклонения больше нет, Ловкость влияет на темп
атак, а не на защиту. Крит: шанс = 2%×УДА (без капа — следить при
балансировке), критический удар ×2 от броска урона. Пассивной
регенерации нет: HP между боями не восстанавливается, лечит только зона
отдыха.

Инвентарь — 2 слота:

- **ближнее оружие** — урон от N до M (оба + Сила), не ломается;
- **броня** — фиксированное поглощение `armor`: столько урона моба
  снимается с каждого удара по герою (минимум 0).

Стартовый набор: ближнее оружие «Кулаки» и «Картонная броня» (броня 0) —
обычные предметы пула (`items/fists.toml`, `items/cardboard_armor.toml`
со `starter = true`, правятся как любые другие; стартовые предметы в
магазине не продаются). Набор собирается по одному
предмету на слот, ближнее оружие обязательно (без него бой не стартует) —
нарушения дают экран ошибки; если в пуле вообще нет предметов со
`starter = true`, берутся встроенные «Кулаки» 1–2. При покупке/экипировке
новый предмет заменяет старый в том же слоте, если тот был; заменённый
предмет теряется.

Уровень: за убийство моба — опыт и золото. Порог апа
`xp_to_next = 10 × текущий уровень`, при апе порог вычитается из
накопленного опыта (можно апнуть несколько уровней за один килл). На каждый
уровень — одно окно прокачки: чат голосует словом, какую из 5 стат
поднять на +1 (`levelup_duration` сек). При апе Выносливости текущее HP
растёт вместе с максимумом (+5 и туда, и туда). Нет голосов — общее
правило овертайма: окно ждёт ещё `overtime_duration`, затем стата
выбирается случайно рулеткой среди всех пяти.

## Бой (событие «моб») — автобой

Голосований в бою нет: бой непрерывный, у каждого участника — свой
кулдаун атаки (КД). Когда КД юнита доходит до нуля, он бьёт, и его КД
перезаряжается (остаток кадра сохраняется — длинный кадр может дать
несколько атак). Порядок разрешения атак внутри кадра фиксирован: герой →
чаттеры отряда (в порядке вступления) → моб. Бой идёт сам, даже если чат
полностью молчит.

- **КД героя**: `hero_cooldown` − `agility_cd_reduction`×ЛОВ, не ниже
  `min_cooldown` (см. «Герой»); рассчитывается при начале боя и фиксирован
  на бой.
- **Удар героя**: случайный урон в диапазоне оружия (N..M + Сила), с
  броском крита (×2 от Удачи).
- **КД моба**: поле `cooldown` в TOML моба (см. «Пулы контента»); у пула
  разные темпы: скелет быстрый (3.5 с), гоблин 5.0, орк 6.0, слайм
  медленный (7.0). При скейле моба под уровень героя КД не масштабируется.
- **Удар моба**: случайный урон в его диапазоне
  (`damage_min`..`damage_max`), из урона вычитается броня героя
  (`armor`, минимум 0). Уклонения нет. Моб бьёт только героя — у чаттеров
  отряда HP нет, они неуязвимы.
- Моб убит → награда (опыт + золото), возможный ап уровня (окно
  прокачки), короткая пауза итога боя (`combat_end_pause`), возврат в
  EVENT.
- Герой убит → GAME_OVER.

**Отряд чата.** В любой момент боя зритель один раз пишет в чат команду
`бой` (регистр и пробелы не важны) и вступает в отряд героя — его юнит
(ник + детерминированный по нику эмодзи) встаёт на поле рядом с героем и
бьёт моба самостоятельно, по своему КД. Статы чаттера случайные, но
откалиброванные: КД бросается равномерно в [`chatter_cd_min`,
`chatter_cd_max`] (дефолт 3.0–8.0 с), а диапазон урона подгоняется так,
чтобы средний DPS чаттера был `chat_damage_pct`% (5%) от среднего DPS
героя: `avg = (средний урон героя / КД героя) × pct/100 × cd`,
`lo = max(1, int(avg))`, `hi = max(lo, 2×round(avg) − lo)` — среднее
`(lo+hi)/2 ≈ avg`, минимальный разовый урон 1 гарантирован. Первый удар —
со случайной доли КД (стартовый разброс, чтобы удары отряда не сливались
в один). Атакуют не более `chat_damage_cap_pct // chat_damage_pct`
(по дефолту 100//5 = 20) членов отряда; вступившие сверх капа стоят на
поле приглушёнными и не бьют (в консоль печатается «squad full»).
Процентная калибровка, а не флэт: чаттеры одинаково ощутимы и на 1 уровне
с Кулаками, и на высоком с прокачанным оружием.

Мобы берутся из пула случайно. Чтобы забег не превращался в бесконечную
лёгкую прогулку, характеристики моба масштабируются от уровня героя:
HP, обе границы урона и награды (опыт, золото) ×(1 + 0.15 × (уровень − 1))
— стартовая формула, тюнить; кулдаун не масштабируется.

Баланс без чата: стартовые числа (Кулаки 2–3, Картонная броня 0, мобы
hp 4–9, урон 1–6) подобраны так, что бой без отряда на 1 уровне примерно
равный — отряд сдвигает чашу весов в победу. Известный риск баланса:
20 активных чаттеров × 5% DPS ≈ +100% DPS героя — мобы с малым HP будут
умирать мгновенно; возможно, HP мобов придётся поднять отдельной
балансировкой. Тюнить по ощущениям со стрима.

## Боевые клички монстров

На дверях мобы показываются базовыми именами («Гоблин», «Слайм»). При
открытии моб-двери боец получает боевую кличку: **случайный префикс + ник
случайного чаттера** — «Гнусный Petya22113» (тип читается по иконке моба).
Если база чаттеров пока пуста — «Гнусный Гоблин».

- **Префиксы** — один файл `prefixes.toml` со списком строк (см. «Пулы
  контента»), перечитывается вместе с пулами на каждом EVENT.
- **База чаттеров** — реестр из streamkit (`ChatterRegistry`): в него
  попадает ник каждого написавшего в чат (не только голосующих). В живом
  режиме база персистится в `chatters.json` рядом с приложением (переживает
  перезапуски, gitignored); в мок-режиме (`--mock`/`--smoke`) реестр только
  в памяти — viewerN в файл не пишутся.
- **Выбор ника**: сначала случайный из активных в текущем запуске; если за
  сессию ещё никто не писал — случайный из всей сохранённой базы.
- **Поверженные**: клички убитых за забег мобов показываются списком на
  экране итогов (GAME_OVER).

## Магазин (тип события)

Показывается список случайных разных предметов из пула (до 9) с ценами.
Предметы дороже текущего золота героя на экран не выводятся, и голоса за
них не учитываются. Чат голосует словом: за покупку показанного предмета
или за выход из магазина (`shop_duration` сек). Покупка экипируется в
слот (старый предмет теряется), магазин закрывается. Нет голосов — общее
правило овертайма: после `overtime_duration` без голосов рулетка
случайно выбирает между покупкой одного из показанных предметов и
выходом. Если покупать нечего (всё дороже золота героя) —
показывается только пункт выхода. После закрытия магазина — короткая
пауза (`combat_end_pause`) и возврат в EVENT.

## Зона отдыха (тип события)

Полностью восстанавливает HP и ману, короткая пауза (`combat_end_pause`),
возврат в EVENT. Голосований внутри нет.

## Типы событий

- **моб** — автобой;
- **магазин** — покупка снаряжения;
- **зона отдыха** — восстановление HP/маны;
- дальше: ловушки, сундуки, боссы, интерактивные объекты.

Правило набора 3 дверей: для каждой двери сначала выбирается подтип —
враг (моб) с вероятностью 70%, интерактив — 30%; при интерактиве случайно
выбирается событие из доступных (зона отдыха — всегда; магазин — только
если пул предметов не пуст). Типы могут повторяться (например, 2 моба +
магазин). Затем моб-двери заполняются случайными мобами без повторов в
тройке; если моб-дверей выпало больше, чем мобов в пуле, остаток
добирается с повторами. Дверь показывает иконку типа и название.

## Пулы контента

По аналогии с историями: один файл = одна сущность, добавить = положить
файл. Пулы перечитываются при каждом входе в EVENT — состав можно менять
без рестарта.

### Моб — `apps/mini_rpg/mobs/<имя>.toml`

```toml
name = "Гоблин"        # обязательно
icon = "👺"            # эмодзи на двери и в бою
hp = 20                # обязательно
damage_min = 2         # обязательно — диапазон урона за удар
damage_max = 4         # (max >= min)
xp = 8                 # награда за убийство
gold = 5
cooldown = 5.0         # кулдаун атаки моба, сек (число > 0, дефолт 5.0)
```

### Предмет — `apps/mini_rpg/items/<имя>.toml`

```toml
name = "Ржавый меч"    # обязательно
icon = "🗡️"
slot = "melee"         # melee | armor, обязательно
damage_min = 3         # для melee — диапазон урона
damage_max = 7
armor = 2              # для armor, обязательно — флэт-поглощение удара моба
price = 15             # обязательно
starter = true         # необязательно — предмет стартового набора героя
                       # (по одному на слот, melee обязателен), в магазин
                       # не попадает; без starter-предметов в пуле —
                       # встроенные «Кулаки» 1–2
```

Проверка пулов: `py -m apps.mini_rpg.core` (по аналогии с историей).

### Префиксы кличек — `apps/mini_rpg/prefixes.toml`

Один файл на весь список (префикс — просто строка, «один файл = одна
сущность» здесь избыточен):

```toml
prefixes = ["Гнусный", "Смешной", "Горючий"]
```

Отсутствующий файл или пустой список — встроенный фолбэк в коде; битый
TOML или не-строки — экран ошибки, как у мобов/предметов.

## Конфиг (`config.toml`)

`channel`, `event_duration` (15.0), `hero_cooldown` (5.0 — базовый
кулдаун атаки героя, сек), `agility_cd_reduction` (0.5 — −сек к КД героя
за очко Ловкости), `min_cooldown` (1.0 — нижний предел КД героя),
`chatter_cd_min` / `chatter_cd_max` (3.0 / 8.0 — диапазон броска КД
чаттера отряда), `chat_damage_pct` (5 — DPS каждого чаттера отряда = %
от среднего DPS героя), `chat_damage_cap_pct` (100 — макс. число
атакующих в отряде = cap // pct),
`levelup_duration` (15.0), `shop_duration` (25.0), `overtime_duration`
(5.0 — овертайм голосования при 0 голосов, один раз на раунд),
`combat_end_pause`
(4.0), `gameover_pause` (15.0), `vote_mode` ("words" — случайные слова
раунда / "classic" — фиксированные команды, см. «Режимы голосования»),
`base_hp` (20), `seed`, `overlay_port`,
`mock_chat`. В скобках — предлагаемые дефолты, тюнить по ощущениям со
стрима.

## Запуск

```bash
py -m apps.mini_rpg           # игра (mock_chat=false → живой Twitch)
py -m apps.mini_rpg --mock    # принудительно мок-чат (эмуляция без Twitch)
py -m apps.mini_rpg --smoke   # авто-выход через 20 с, всегда мок-чат
py -m apps.mini_rpg.core      # проверка пулов mobs/ и items/
```

При старте печатается адрес оверлея — открыть в браузере для предпросмотра
или добавить в OBS источником «Браузер». Под оверлей стример кладёт
источник с камерой — она видна сквозь прозрачную рамку аватарки.

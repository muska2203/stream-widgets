# Мини-RPG — DESIGN

Зрители чата Twitch коллективно ведут одного героя через бесконечный забег:
выбирают события-двери, дерутся с мобами, качают характеристики и покупают
снаряжение. Оверлей — локальная веб-страница
(`http://127.0.0.1:<overlay_port>`, адрес печатается при запуске), которую
стример добавляет в OBS источником «Браузер» (Browser Source);
прозрачность нативная, хромакей не нужен.

Аватарка героя на оверлее — пустая прозрачная рамка: стример кладёт под
оверлей источник с камерой, и его лицо оказывается «лицом» героя. Игра сама
камеру не захватывает и ничего в рамку не рисует.

Статус: реализовано (см. DEVELOPMENT.md). Все числа баланса ниже —
стартовые дефолты, крутятся в конфиге и контентных файлах.

## Цикл игры

```
RUN_START → EVENT → (COMBAT | SHOP | REST | ...) → EVENT → ...
                                              ↘ GAME_OVER → RUN_START (новый герой)
```

- **RUN_START** — создаётся новый герой 1 уровня со стартовым набором
  (см. «Герой»).
- **EVENT** — на экране 3 двери со случайными событиями (мобы, магазин,
  зона отдыха — правило набора в «Типы событий»), чат голосует цифрой
  (`1`..`3`, `event_duration` сек). Победившая дверь открывается, событие
  запускается. Дверь показывает иконку и название события (у моба — его
  иконка и имя, у магазина/отдыха — свои). Пустой пул мобов — экран
  ошибки (как в истории).
- **GAME_OVER** — герой умер: экран с итогами забега (уровень, убито
  мобов, заработано золота, список поверженных по боевым кличкам), пауза
  `gameover_pause` сек, затем новый RUN_START. Рестарт автоматический,
  стриму ничего делать не нужно.

**Нет голосов — выбор не происходит**: голосование перезапускается с тем
же составом (те же 3 двери). Переголосование разрешено, при ничьей
победитель случаен среди лидеров (правило streamkit). Лидеры
подсвечиваются все сразу; при ничьей по окончании голосования игра держит
фазу на `tie_resolve_pause` секунд (~3 с) — на оверлее играет «рулетка»:
пункты-лидеры по очереди моргают с затуханием темпа, остановка на
выпавшем победителе, затем исход применяется. Исключения — бой
(ход без голосов пропускается, чтобы бой не вставал) и магазин (нет
голосов = выход без покупки).

## Герой

Характеристики (нарочито тупые, одна характеристика = один эффект):

| Стата | Эффект |
|-------|--------|
| Сила | + урон оружием ближнего боя |
| Ловкость | + урон оружием дальнего боя |
| Интеллект | + мана (тратить пока нечем — задел под способности) |
| Выносливость | + максимум HP |
| Удача | + шанс крита |

Старт: все статы 0, уровень 1, золото 0, HP = `base_hp` (20) + 5×ВЫН,
мана = 5×ИНТ. Крит: шанс = 2%×УДА (без капа — следить при балансировке),
критический удар ×2 от итогового урона (бросок + стата). Пассивной
регенерации нет: HP между боями не восстанавливается, лечит только зона
отдыха.

Инвентарь — 3 слота:

- **ближнее оружие** — урон от N до M (бросок) + Сила, не ломается;
- **дальнее оружие** — урон от N до M + Ловкость, заметно мощнее
  ближнего, но имеет ограниченное число использований (`uses`); каждая
  попытка атаки тратит 1 использование — даже отражённая блоком
  (выстрелил — потратил), при нуле оружие разрушается (слот пустеет);
- **броня** — плоское снижение входящего урона: из каждого неотражённого
  удара врага вычитается значение брони (минимум 0).

Стартовый набор: ближнее оружие «Кулаки» (1–2), дальнего оружия и брони
нет. При покупке/экипировке новый предмет заменяет старый в том же слоте,
если тот был; заменённый предмет теряется.

Уровень: за убийство моба — опыт и золото. Порог апа
`xp_to_next = 10 × текущий уровень`, при апе порог вычитается из
накопленного опыта (можно апнуть несколько уровней за один килл). На каждый
уровень — одно окно прокачки: чат голосует цифрой (`1`..`5`), какую стату
поднять на +1 (`levelup_duration` сек). При апе Выносливости текущее HP
растёт вместе с максимумом (+5 и туда, и туда). Нет голосов — окно
перезапускается, игра дальше не идёт, пока стату не выбрали.

## Бой (событие «моб»)

Ходы чередуются, первый — за героем. Оба участника в каждом ходу тайно
выбирают одно из 3 направлений: **голова / тело / ноги**.

- **Ход героя (атака)**: чат одной командой выбирает оружие и направление
  (`combat_duration` сек):
  - `1` `2` `3` — ближнее оружие по голове / телу / ногам;
  - `4` `5` `6` — дальнее оружие по голове / телу / ногам.
  Моб в это время случайно выбирает направление защиты. Если оно совпало
  с направлением атаки — удар отражён, урона нет. Иначе урон =
  бросок N..M оружия + стата, с проверкой крита. Голосы `4`..`6` не
  учитываются, если дальнего оружия нет или у него 0 использований (на
  экране эти варианты тогда не показываются).
- **Ход моба (защита)**: чат выбирает, какое направление защитить
  (`1` `2` `3` — голова / тело / ноги). Моб случайно выбирает направление
  атаки. Совпало — удар отражён полностью. Не совпало — урон моба
  (бросок N..M) минус броня героя.
- **Нет голосов** — ход пропускается: в атаке герой не бьёт, в защите
  ничего не заблокировано. Бой не встаёт.
- Моб убит → награда (опыт + золото), возможный ап уровня (окно
  прокачки), короткая пауза итога боя (`combat_end_pause`), возврат в
  EVENT.
- Герой убит → GAME_OVER.

Мобы берутся из пула случайно. Чтобы забег не превращался в бесконечную
лёгкую прогулку, характеристики моба масштабируются от уровня героя:
HP, урон и награды (опыт, золото) ×(1 + 0.15 × (уровень − 1)) — стартовая
формула, тюнить.

## Боевые клички монстров

На дверях мобы показываются базовыми именами («Гоблин», «Слайм»). При
открытии моб-двери боец получает боевую кличку: **случайный префикс + ник
случайного чаттера** — «Гнусный Petya22113» (тип читается по иконке моба).
Если база чаттеров пока пуста — «Гнусный Гоблин».

- **Префиксы** — один файл `prefixes.toml` со списком строк (см. «Пулы
  контента»), перечитывается вместе с пулами на каждом EVENT.
- **База чаттеров** — реестр из streamkit (`ChatterRegistry`): в него
  попадает ник каждого написавшего в чат (не только голосующих). В живом
  режиме база персистится в `chatters.json` рядом с приложением (переживает
  перезапуски, gitignored); в мок-режиме (`--mock`/`--smoke`) реестр только
  в памяти — viewerN в файл не пишутся.
- **Выбор ника**: сначала случайный из активных в текущем запуске; если за
  сессию ещё никто не писал — случайный из всей сохранённой базы.
- **Поверженные**: клички убитых за забег мобов показываются списком на
  экране итогов (GAME_OVER).

## Магазин (тип события)

Показывается список случайных разных предметов из пула (до 9) с ценами.
Предметы дороже текущего золота героя на экран не выводятся, и голоса за
них не учитываются. Чат голосует: `1`..`9` — купить предмет, `0` — выйти
из магазина (`shop_duration` сек). Покупка экипируется в слот (старый
предмет теряется), магазин закрывается. Выход — или нет голосов вовсе —
закрывает магазин без покупки (магазин не ждёт голосов бесконечно). Если
покупать нечего (всё дороже золота героя) — показывается только пункт
`0` — выйти. После закрытия магазина — короткая пауза
(`combat_end_pause`) и возврат в EVENT.

## Зона отдыха (тип события)

Полностью восстанавливает HP и ману, короткая пауза (`combat_end_pause`),
возврат в EVENT. Голосований внутри нет.

## Типы событий

- **моб** — бой;
- **магазин** — покупка снаряжения;
- **зона отдыха** — восстановление HP/маны;
- дальше: ловушки, сундуки, боссы, интерактивные объекты.

Правило набора 3 дверей: для каждой двери сначала выбирается подтип —
враг (моб) с вероятностью 70%, интерактив — 30%; при интерактиве случайно
выбирается событие из доступных (зона отдыха — всегда; магазин — только
если пул предметов не пуст). Типы могут повторяться (например, 2 моба +
магазин). Затем моб-двери заполняются случайными мобами без повторов в
тройке; если моб-дверей выпало больше, чем мобов в пуле, остаток
добирается с повторами. Дверь показывает иконку типа и название.

## Пулы контента

По аналогии с историями: один файл = одна сущность, добавить = положить
файл. Пулы перечитываются при каждом входе в EVENT — состав можно менять
без рестарта.

### Моб — `apps/mini_rpg/mobs/<имя>.toml`

```toml
name = "Гоблин"        # обязательно
icon = "👺"            # эмодзи на двери и в бою
hp = 20                # обязательно
damage_min = 2         # обязательно
damage_max = 5         # обязательно, >= damage_min
xp = 8                 # награда за убийство
gold = 5
```

### Предмет — `apps/mini_rpg/items/<имя>.toml`

```toml
name = "Короткий лук"  # обязательно
icon = "🏹"
slot = "ranged"        # melee | ranged | armor, обязательно
damage_min = 3         # для melee/ranged
damage_max = 7
uses = 5               # для ranged, обязательно
armor = 2              # для armor, обязательно
price = 15             # обязательно
```

Проверка пулов: `py -m apps.mini_rpg.core` (по аналогии с историей).

### Префиксы кличек — `apps/mini_rpg/prefixes.toml`

Один файл на весь список (префикс — просто строка, «один файл = одна
сущность» здесь избыточен):

```toml
prefixes = ["Гнусный", "Смешной", "Горючий"]
```

Отсутствующий файл или пустой список — встроенный фолбэк в коде; битый
TOML или не-строки — экран ошибки, как у мобов/предметов.

## Конфиг (`config.toml`)

`channel`, `event_duration` (15.0), `combat_duration` (12.0 — одно
голосование в бою), `combat_outcome_pause` (2.5 — показ итога хода),
`levelup_duration` (15.0), `shop_duration` (25.0), `combat_end_pause`
(4.0), `gameover_pause` (15.0), `base_hp` (20), `seed`, `overlay_port`,
`mock_chat`. В скобках — предлагаемые дефолты, тюнить по ощущениям со
стрима.

## Запуск

```bash
py -m apps.mini_rpg           # игра (mock_chat=false → живой Twitch)
py -m apps.mini_rpg --mock    # принудительно мок-чат (эмуляция без Twitch)
py -m apps.mini_rpg --smoke   # авто-выход через 20 с, всегда мок-чат
py -m apps.mini_rpg.core      # проверка пулов mobs/ и items/
```

При старте печатается адрес оверлея — открыть в браузере для предпросмотра
или добавить в OBS источником «Браузер». Под оверлей стример кладёт
источник с камерой — она видна сквозь прозрачную рамку аватарки.

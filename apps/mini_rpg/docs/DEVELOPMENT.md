# Мини-RPG — DEVELOPMENT

Контракты модулей, грабли, как развивать. Общие правила репо — в корневом
AGENTS.md (тесты `py -m unittest discover`, агент не запускает UI).

Статус: реализовано — все этапы PLAN.md пройдены, история реализации и
отклонения от первоначального плана — в строках «факт» PLAN.md. Правила
игры и форматы контента — в DESIGN.md.

## Модули

- `core/hero.py` — чистая модель (без IO): `Hero` (статы, уровень, опыт,
  золото, HP/мана, 2 слота снаряжения: melee/armor), фабрика
  `new_hero(base_hp, starters=None)` — экипирует копии стартовых предметов
  (по одному на слот; без аргумента — `[DEFAULT_STARTER]`, «Кулаки» 1–2).
  Формулы HP/маны/крита/КД атаки —
  здесь же, константами (`HP_PER_ENDURANCE`, `MANA_PER_INTELLECT`,
  `CRIT_PER_LUCK`, `CRIT_MULTIPLIER`, `XP_PER_LEVEL`),
  одно место для баланса. Бой — броски: `damage_range()` →
  (min+Сила, max+Сила) melee-оружия, `armor_value` → флэт брони (0 без
  неё), `strike(rng)` — случайный урон в диапазоне + бросок крита ×2
  (rng передаётся аргументом), `attack_cooldown(base, per_agility,
  min_cd)` → `max(min_cd, base − Ловкость×per_agility)` — КД атаки героя
  (фиксируется Combat'ом на бой).
- `core/content.py` — загрузка пулов: `load_mob(path)`, `load_item(path)`,
  `discover_mobs(dir)`, `discover_items(dir)`, `load_mobs/load_items`,
  `load_prefixes(path)` (список префиксов боевых кличек из одного TOML;
  отсутствующий файл/пустой список → встроенный `DEFAULT_PREFIXES`, битый
  TOML → `ContentError`), `find_starters(items)` (стартовый набор героя:
  предметы пула со `starter = true`, по одному на слот, melee обязателен,
  иначе `ContentError`; нет ни одного → `[DEFAULT_STARTER]`, как
  `DEFAULT_PREFIXES`), `ContentError`.
  Валидация при загрузке
  (обязательные поля: у моба диапазон `damage_min`/`damage_max`,
  у оружия `damage_max >= damage_min`, у брони `armor >= 0`,
  корректный `slot` из `SLOTS = melee/armor`) —
  битый файл роняет игру в экран ошибки с понятным сообщением, как в
  истории.
- `core/combat.py` — `Combat(hero, mob, rng, hero_cooldown,
  agility_cd_reduction, min_cooldown, chatter_cd_min, chatter_cd_max,
  chat_pct, chat_cap, level_scale)`: автобой одного энкаунтера в
  непрерывном времени, у каждого юнита свой кулдаун. `update(dt)` →
  список `CombatEvent(seq, attacker, target, damage, crit,
  armor_absorbed, target_hp)`: `cd_left -= dt` у героя/моба/активных
  чаттеров, юнит с `cd_left <= 0` атакует и добирает `cd_left +=
  cooldown` (while — длинный кадр даёт несколько атак), порядок в кадре
  фиксирован: герой (`hero.strike`, крит) → чаттеры (порядок вступления,
  `randint` без крита) → моб (только по герою, флэт-броня, минимум 0;
  уклонения нет). Смерть цели → `_finish`, остаток кадра отменяется;
  `update` после конца — `RuntimeError`. Отряд чата: `join(user)` → bool
  (один раз за бой) создаёт `ChatterUnit(nick, emoji, damage_min,
  damage_max, cooldown, cd_left, active)`: КД — `uniform(chatter_cd_min,
  chatter_cd_max)`, урон откалиброван под DPS = `chat_pct`% среднего DPS
  героя (`avg = (lo+hi)/2 / hero_cd × pct/100 × cd`; `lo = max(1,
  int(avg))`, `hi = max(lo, 2×round(avg) − lo)`), `cd_left` стартует со
  случайной доли КД, `active = (уже активных) < chat_cap // chat_pct` —
  сверх капа юнит создаётся неатакующим и в консоль печатается «squad
  full». Эмодзи чаттера детерминирован ником (`zlib.crc32` → пул
  `CHATTER_EMOJI`). `rewards` (скейл), `finished`, `hero_won`, `hero_cd`,
  `hero_cd_left`, `mob_cd_left`, `squad` (список в порядке вступления).
  Ничего не знает про чат и время — цикл крутит `game.py`. Моб скейлится
  при создании (`scale_mob`): hp/обе границы урона/награды ×(1 +
  0.15×(уровень героя − 1)), округление — `int(x·k + 0.5)` (до ближайшего
  целого, половины вверх; на границах вида x·k = y.5 возможен
  float-артефакт вниз, это норма); `cooldown` прокидывается без скейла.
  `Game` скейлит моба уже при броске
  дверей и передаёт в бой готового (`level_scale=0`), чтобы threat на
  двери совпадал с боем.
- `core/choices.py` — канонические ключи голосований под фазы: двери
  `1..3` (`door_keys`), прокачка `1..5`
  (`levelup_keys`), магазин `0..n` (неподъёмные цены отсечены до
  построения списка — набор ключей знает только показанные позиции,
  `shop_keys`). В бою голосований нет (автобой), команда вступления в
  отряд — фиксированная `JOIN_COMMAND = "бой"` в game.py, этому модулю
  не принадлежит. Здесь же таблицы классического режима (`*_commands()` →
  {ключ: команда}): двери — «левая/средняя/правая», прокачка —
  названия стат, магазин — «1..N» и «выход». Зрители голосуют
  командами-алиасами, не цифрами напрямую: валидатор раунда строит `Game`
  (случайные слова `streamkit.VoteWords` в режиме "words", фиксированные
  таблицы в "classic"), этот модуль определяет КАКИЕ ключи у фазы есть и
  КАКИЕ классические команды им соответствуют. Маппинг ключей:
  `levelup_choice` → STATS[i].
- `core/__main__.py` — CLI-проверка пулов: `py -m apps.mini_rpg.core
  [mobs_dir [items_dir [prefixes_path]]]` (мобы, предметы, префиксы),
  exit 1 при ошибках/пустом пуле; stdout в
  `errors="replace"` — консоль cp1251 не печатает эмодзи иконок.
- `config.py` — `@dataclass Config` + `load_config()` (streamkit
  `load_toml_config`; неизвестные ключи TOML игнорируются). `vote_mode`
  ("words"/"classic", `VOTE_MODES`) валидируется в `load_config` —
  неизвестное значение → ValueError. Кулдауны боя: `hero_cooldown` (5.0),
  `agility_cd_reduction` (0.5 с за очко Ловкости), `min_cooldown` (1.0),
  `chatter_cd_min`/`chatter_cd_max` (3.0/8.0); `chat_damage_pct` (5) —
  DPS чаттера отряда в % от среднего DPS героя, `chat_damage_cap_pct`
  (100) — кап числа атакующих = cap // pct.
- `persistence.py` — чекпоинты прогресса забега между сессиями:
  `save_checkpoint(path, game)` / `load_checkpoint(path)`,
  `default_save_path()`, `SAVE_VERSION`. Сохраняется только долгоживущее:
  герой (вложенные Item слотов — через `dataclasses.asdict`) + счётчики
  забега (`kills`, `gold_earned`, `deaths`, `defeated`, `pending_levelups`);
  состояние
  автомата не персистится. Атомарная запись tmp + replace (паттерн
  `ChatterRegistry.save`), ошибки записи — только warning. Загрузка
  валидирует версию/типы (мёртвый герой `hp < 1` отклоняется), клампит
  hp/mana к максимумам (баланс мог измениться); битый/устаревший файл
  переименовывается в `.bak` и возвращается None — сейв никогда не роняет
  игру.
- `game.py` — `Game(cfg, ui=None, mobs_dir=..., items_dir=...,
  prefixes_path=..., chatters=..., save_path=...)`: автомат
  RUN_START (транзитный — конструктор сразу входит в EVENT) / EVENT /
  COMBAT (подфазы fight/end) / SHOP / REST / LEVELUP /
  GAME_OVER / ERROR (пулы битые/пусты). Единая точка входа чата
  `handle_chat_message(user, text)` — первой строкой регистрирует автора в
  `chatters` (реестр `streamkit.ChatterRegistry`: база ников пишущих,
  приоритет активных за сессию, фолбэк на всю базу). В фазе COMBAT/fight
  сообщение `бой` (strip().lower()) вступает автора в отряд
  (`combat.join`) — это не голосование, `vote_loop` в бою нет.
  Боевые клички мобов:
  `enter_combat` переименовывает моба копией (`replace(mob, name=...)`) в
  «Префикс Ник» (тип виден по иконке; без базы — «Префикс Тип») — Combat
  дальше копирует имя сам через scale_mob, а дверной mob не мутирует. Клички убитых копятся в `defeated` и уходят в
  `run_summary` (список «поверженных» на экране итогов). Чистый Python:
  главный цикл в `main.py` зовёт `game.update(dt)`. Дверь —
  `@dataclass Door(kind, mob)` с иконкой/именем (у моба — его, у
  магазина/отдыха — свои из DOOR_VIEW);
  моб-дверь уже отскейлена под уровень героя (`scale_mob` при броске
  дверей).
  Персист прогресса (`save_path`): `None` (дефолт — тесты, мок/smoke в
  main.py) — без файла. С путём конструктор зовёт
  `persistence.load_checkpoint`: валидный сейв → герой и счётчики забега
  восстанавливаются и игра входит сразу в `enter_event()` (свежий бросок
  дверей, незавершённый бой переигрывается); нет сейва/битый — обычный
  `enter_run_start()`. Чекпоинт (`_save_checkpoint()`) пишется на границах
  фаз: в `enter_run_start()` (первый старт без сейва — свежий герой
  1 уровня), в `enter_game_over()` (смерть: сейв сразу после штрафа —
  золото и опыт текущего уровня обнулены, счётчики забега kills/
  gold_earned/defeated сброшены, герой возрождён с полными HP/маной,
  уровень/статы/снаряжение и счётчик deaths сохраняются)
  и в `enter_event()` на успешном пути после `state = EVENT` (все
  изменения героя — бой/магазин/отдых/прокачка — к этому моменту
  отыграны; в ERROR-пути чекпоинта нет).
  Голосование алиасами (`vote_mode`): в режиме "words"
  `self.vote_words = VoteWords.from_file(rng=self.rng)`
  (пул — `streamkit/votewords.toml`, ~250 слов; cooldown выдачи 60 с,
  rng общий с игрой — сид конфига покрывает и слова), в "classic"
  `vote_words is None` и действуют фиксированные таблицы core.choices.
  Перед открытием каждого голосования `_assign_words(classic_commands)`
  строит маппинг раунда: в words-режиме раздаёт ключам фазы случайные
  слова, в classic — берёт таблицу как есть (обратный маппинг
  ключ → алиас кладётся в `vote_key_words` для UI)
  и возвращает валидатор алиас → ключ для VoteLoop (`VoteWords.validator`
  в обоих режимах); `_assign_words` зовётся
  ДО `ui.show_*` фазы, чтобы алиасы попали в тот же снапшот, что и варианты.
  `current_vote_words()` — алиасы активного раунда (пул мок-чата в main.py,
  работает в обоих режимах); во время автобоя (COMBAT/fight) возвращает
  `[JOIN_COMMAND]`, чтобы мок-зрители вступали в отряд.
  Автобой: `enter_combat` создаёт `Combat` (кулдауны и калибровка из
  конфига), ставит подфазу FIGHT и `time_left = 0` — таймера фазы в бою
  нет. В FIGHT `update(dt)` продвигает бой каждый кадр:
  `events = combat.update(dt)`; непустые события уходят в
  `ui.show_combat_events(events)`; при `combat.finished` —
  `_finish_combat()` (награды/прокачки/GAME_OVER). `ui.update_timer()` в
  FIGHT не зовётся (и так бы не републиковал — секунда заморожена на 0).
  Шов оверлея — интерфейс `NullUI` (show_*/update_votes/update_timer/
  show_tie_resolve), реализация — `webui.WebUI`. `update_votes` получает
  `leaders` списком — при ничьей подсвечиваются все лидеры; конец раунда
  оборачивается в `_resolve_end`: единственный лидер применяется сразу,
  ничья откладывает исход (`_pending_end`) на `tie_resolve_pause`, пока
  оверлей крутит рулетку, — применяет отложенный исход `update()`.
- `webui.py` — `WebUI(game)`: модель состояния оверлея (чистый Python,
  без сети), атомарная публикация снапшота (deepcopy + своп ссылки), как
  в `interactive_story/webui.py`. Читает Game при публикации (панель
  героя, таймер, флаг `overtime` голосования, подфаза и HP моба в бою); конструктор зовёт `refresh()`,
  восстанавливающий снапшот из текущего состояния Game — Game входит в
  первую фазу ещё до подключения UI. Подписи стат/слотов —
  словари STAT_NAMES/STAT_HINTS/SLOT_NAMES/SHORT_SLOT_NAMES, в снапшот
  попадают готовыми
  строками: у дверей-мобов — `threat` («HP 4 · урон 2–4»), у моба в бою —
  диапазон урона, у товаров магазина — `slot_name`/`detail`/`current`
  (сравнение с экипированным; «урон 2–4» у оружия, «броня 2» у брони).
  Боевой блок снапшота: `subphase` (fight/end), `mob` (icon, name, hp,
  max_hp, damage, cooldown, cd_left), `hero_cd` (cooldown/cd_left героя),
  `squad` (список `{nick, emoji, damage, cooldown, cd_left, active}` в
  порядке вступления) и `events` (последние 50 `CombatEvent`: seq,
  attacker, target, damage, crit, armor_absorbed, target_hp) —
  `show_combat_events` только дописывает новые события в очередь.
  Все `cd_left` округляются до 2 знаков. Подфаза, HP моба и `cd_left`
  юнитов дочитываются из живого `game.combat` в `_publish()` — между
  публикациями событий может не быть, а кольца КД на странице должны
  синкаться. Публикации в бою событийные (таймера нет), поэтому
  `/state.json` отдаёт `ui.fresh_snapshot()`: `cd_left` всех юнитов
  экстраполируется к моменту отдачи (минус возраст последней публикации,
  кламп в 0, хранимый снапшот не мутируется) — иначе замороженное между
  событиями значение дёргало отсчёт колец на странице.
  Диапазоны — через en-тире «–». У каждого
  голосуемого варианта рядом с каноническим ключом `n` есть поле `word`
  (слово-алиас раунда из `game.vote_key_words`, читается через `_words()`
  на момент show_*; `None` в headless-тестах без маппинга) — страница
  показывает слово, а голоса и рулетка по-прежнему идут по `n`. Блок
  `resolve` (ничья: leaders/winner/duration для рулетки) живёт ровно одну
  публикацию — повторная ничья с тем же составом должна перезапускать
  анимацию.
- `server.py` — `OverlayServer(ui, port, host="127.0.0.1")`:
  ThreadingHTTPServer в daemon-потоке, `/` и `/overlay.html` →
  `web/overlay.html` (путь рядом с пакетом), `/state.json` → снапшот
  (JSON utf-8, no-store), прочее → 404, логи запросов заглушены.
  Скопирован подход истории; в streamkit не выносится: файл не идентичен
  (у истории frozen-ветка путей, у mini_rpg её нет), а общий сервер
  появится только с реальным вторым идентичным клиентом.
- `web/overlay.html` — самодостаточная страница (CSS+JS inline, Rubik
  с фолбэком system-ui/sans-serif, опрос `/state.json` каждые 200 мс)
  в «комикс»-стиле по макету `designs/comic-v1.html` (приглушённая
  серо-бежево-пыльная палитра, единственный яркий акцент — клавиши
  вариантов `.key` и лидер голосования; бумажные карточки, жирная
  чёрная обводка, твёрдые тени; служебные элементы макета —
  devbar, превью OBS, заглушка камеры — в прод не переносятся): слева
  постоянная панель героя (прозрачная рамка аватарки — под неё в OBS
  кладётся камера, звёздный бейдж уровня, полосы HP/маны/опыта, чипы
  золота и смертей, стикеры-чипы статов, слоты снаряжения, статичная плашка
  «как играть» — управление словами в чате и вступление в отряд), справа
  экраны фаз
  (двери, сцена боя battle-v2, прокачка,
  магазин, отдых, итог забега, ошибка). Сцена боя — по макету
  `designs/battle-v2.html`: зоны отряда и врага по краям, «VS» посередине;
  юниты — круглые жетоны (ник, пилюля урона, кольцо КД) с локальным
  отсчётом на rAF, мягким ресинком из `cd_left` снапшота (жёсткий снап
  только при расхождении > 1.2 с — свежесть значений обеспечивает
  `fresh_snapshot` на сервере) и сбросом кольца в полный КД на событии
  атаки юнита; чаттеры — кирпичной
  сеткой с zoom-out при переполнении, ключуются ником через Map (герой и
  моб — единственные экземпляры); удары идут по очереди `events` с
  курсором `lastEventSeq` и стаггером 190 мс (выпад, «БАМ!», dmg-float,
  крит, «броня −N»); в fight глобального таймера нет, в end — печать
  «🏆 ПОБЕДА!». Лога тиков нет. DOM пересобирается только по
  структурным подписям (голоса/HP/таймер — точечно). Python про
  пиксели ничего не
  знает. Клавиша `.key` показывает слово-алиас варианта (`o.word`,
  ширина кнопки резиновая под слово 3–7 букв), канонический ключ лежит в
  `data-n` строки — по нему рулетка матчит лидеров и победителя
  (`resolve` приходит с каноническими ключами; при случайном выборе после
  овертайма в `leaders` приходят ВСЕ варианты — рулетка работает без
  изменений). При `s.overtime` бейдж таймера мигает и подрагивает
  (CSS-класс `#timer-badge.overtime`, анимации overtime-blink +
  overtime-shake). Структурные подписи
  включают `word`: состав вариантов может не измениться при новых словах,
  а DOM пересобраться обязан. Рулетка при ничьей — JS поверх точечных
  обновлений (`startRoulette` по блоку `resolve` из снапшота): лидеры
  моргают по очереди, паузы между вспышками нарастают (торможение к
  финалу), остановка на `winner`; пока `rouletteActive`, классом
  `.leader` владеет анимация (`updateRows` его не трогает), таймер скрыт;
  отпускает рулетку `apply()`, когда голоса/состояния в снапшоте
  сменились — Python применил победителя.
- `main.py` — entry point: конфиг → реестр чаттеров (живой Twitch —
  `ChatterRegistry(chatters.json)` с персистом, мок-режим — в памяти, чтобы
  viewerN не засоряли файл) → `Game(cfg, chatters=..., save_path=...)`
  (сейв `savegame.json` — тоже только в живом режиме, мок/smoke —
  `save_path=None`) → `WebUI(game)` →
  `game.ui = ui` → чат → `OverlayServer` → цикл на `time.monotonic` ~60 Гц
  (`chat.update(dt)` + `game.update(dt)`), `server.stop()` в finally.
  Чат создаётся здесь, а не внутри Game (отличие от истории): `MockChat`
  при `cfg.mock_chat`/`--mock`/`--smoke`, иначе `TwitchChat` на
  `cfg.channel`. У мок-чата свой rng (`random.Random(cfg.seed)`), чтобы
  трафик чата не сдвигал броски игры. Пул сообщений мока — callable
  (`_mock_pool(game)`, поддержка callable-пулов добавлена в
  `streamkit.MockChat` опционально, списки работают по-прежнему):
  перечитывается каждый тик и возвращает алиасы активного голосования
  (`game.current_vote_words()`, утроенные — преимущественно валидные
  голоса; в бою — команда `бой`) плюс мусор (в words-режиме — включая
  цифры: проверка, что они не принимаются). `--smoke` — авто-выход через
  20 с, всегда мок-чат (живой Twitch не трогает).

## Игровой цикл — точные правила

- Весь тайминг через `dt` в `Game.update(dt)`; никаких sleep/потоков в
  игровой логике.
- `VoteLoop` создаётся заново на каждую фазу голосования: у дверей,
  прокачки и магазина свой набор канонических ключей и свежая
  раздача слов (`_assign_words` в `_open_*_vote`/`enter_shop`). В бою
  голосований нет — бой продвигается каждый кадр через `combat.update(dt)`
  (у каждого юнита свой кулдаун), `time_left` в FIGHT заморожен на 0.
- Таймеры единые по фазе, как в истории: `time_left` тикает в `Game`,
  голосование закрывается явным `vote_loop.finish()` при `time_left <= 0`.
  Таймер на оверлей: `Game.update()` пушит `ui.update_timer()` каждый
  кадр (кроме FIGHT — там `time_left` = 0 и `update_timer` не зовётся),
  WebUI републикует снапшот при смене показываемой секунды или
  флага `overtime` (дедупликация, как set_header у истории).
- «Нет голосов» — единое правило для всех голосований (двери, магазин,
  прокачка), реализовано в `_resolve_end` один раз:
  раунд без голосов → овертайм на `cfg.overtime_duration` (флаг
  `game.overtime=True`, свежий `VotingRound` с ТЕМ же валидатором — слова
  и варианты сохраняются, голосов всё равно 0); голос появился → обычное
  завершение; голосов снова 0 → случайный победитель среди ВСЕХ ключей
  раунда той же рулеткой, что ничья (`show_tie_resolve(leaders=все
  варианты, winner)`). Обработчики `on_*_end` всегда получают winner.
- Ничья: `_resolve_end` (обёртка коллбэка раунда в `_open_vote`) при
  ≥2 лидерах (или при случайном выборе после овертайма — там leaders это
  все варианты) обнуляет `vote_loop`, ставит `time_left =
  cfg.tie_resolve_pause`, складывает исход в `_pending_end` и зовёт
  `ui.show_tie_resolve(leaders, winner)`; `update()` по истечении паузы
  шлёт `update_votes(counts, [winner])` (в UI остаётся один победитель) и
  вызывает отложенный коллбэк. Во время паузы чат игнорируется
  (`vote_loop is None`), фаза на экране не меняется.
- Автобой: бой продвигается каждый кадр — `Game.update(dt)` в подфазе
  FIGHT зовёт `combat.update(dt)`, непустой список событий уходит в UI
  через `show_combat_events(events)` и виден до следующего кадра; при
  `combat.finished` — `_finish_combat()` (награды/прокачки/GAME_OVER).
  Смерть цели внутри кадра отменяет остаток кадра. Отдельной паузы-итога
  нет, события и есть темп боя.
- Конец выигранного боя — подфаза `end` внутри COMBAT (`combat_end_pause`,
  state остаётся COMBAT): награды и прокачки уже отыграны, оверлей
  показывает «Победа!». До UI подфаза `end` доходит без вызова ui:
  подфаза, HP моба и `cd_left` юнитов синкаются из Game в
  `WebUI._publish()`.
- Пулы `mobs/` и `items/` перечитываются при каждом входе в EVENT —
  состав меняется без рестарта игры. Там же перечитывается
  `prefixes.toml` (префиксы боевых кличек). Предметы с `starter = true`
  в магазинный пул не попадают: это стартовый набор героя
  (`items/fists.toml` + `items/cardboard_armor.toml`), его
  `enter_run_start` собирает через `find_starters` (нет starter-предметов
  в пуле — встроенный дефолт; дубль слота или набор без melee — экран
  ошибки, CLI пулов проверяет набор отдельной строкой).
- Набор дверей — по правилу из DESIGN.md «Типы событий»: сначала подтип
  каждой двери (моб с шансом `MOB_CHANCE` = 70%, иначе интерактив —
  случайный из зоны отдыха и магазина, магазин только если пул предметов
  не пуст), потом мобы без повторов в тройке (при нехватке пула — добор
  с повторами). Пустой пул предметов — не ошибка: магазин просто не
  выпадает на дверях (битый файл предмета — экран ошибки, как у мобов).
- Покупка в магазине экипирует копию предмета (`dataclasses.replace`):
  шарить Item пула с героем нельзя.
- Пауза после закрытия магазина и после отдыха — `combat_end_pause`
  (свои поля в конфиг не добавляем, пока хватает одной).
- Смерть героя → штраф (обнуляются золото и опыт текущего уровня,
  сбрасывается статистика забега — убито мобов, заработано золота,
  поверженные; герой возрождается с полными HP/маной, чекпоинт пишется
  сразу) → экран итогов (убито, заработано золота, список поверженных —
  сняты до сброса; счётчик смертей `deaths` копится и показывается чипом
  на панели героя) → автоматическое
  возрождение в тот же забег; цикл бесконечный, стриму не нужен рестарт.

## Оверлей (OBS Browser Source)

Окна нет: страница `http://127.0.0.1:<overlay_port>`, стример добавляет её
в OBS источником «Браузер», прозрачность нативная. Рамка аватарки — просто
прозрачная область в вёрстке с рамкой по краю; игра ничего в неё не рисует,
камера стримера — отдельный источник под оверлеем в OBS.

Фазы снапшота: `event` (3 двери с голосами), `combat` (сцена battle-v2:
зоны отряда и врага с полосами HP, круглые юниты с кольцами кулдаунов,
подсказка команды `бой`, очередь событий ударов), `levelup` (5 статов
с голосами), `shop` (товары с ценами и голосами, `0` — выход), `rest`,
`game_over` (итоги забега), `error` (пулы контента битые/пусты).

## Грабли

- Битый/устаревший `savegame.json` не должен ронять стрим: загрузка идёт
  только через `persistence.load_checkpoint` (он валидирует, откладывает
  файл в `.bak` и возвращает None). Прямой `json.load` в `game.py` не
  тащить. Восстановление — только через `enter_event()`: бой/голосование
  из сейва не воссоздаются, голоса прошлой сессии мертвы.
- Атомарная публикация снапшота (`deepcopy` + своп ссылки) — мутировать
  состояние мимо публикации нельзя, страница не увидит изменений.
- `VoteLoop.update(dt)` может вызвать коллбэк, меняющий фазу и обнуляющий
  `game.vote_loop` — после `update()` обращаться к нему только под
  проверкой состояния и `is not None`. Поэтому раунд закрывается явным
  `finish()` из `Game.update()`, а не по внутреннему таймеру VoteLoop.
- Автобой — броски, не шкалы: rng в бою нужен для урона/крита героя,
  урона моба и бросков чаттеров (урон и стартовый `cd_left` при `join`);
  бой продвигается только из `Game.update()` — никаких коллбэков из чата
  (команда `бой` лишь пополняет отряд, юнит начнёт бить со своим КД).
- Эмодзи чаттера детерминируется через `zlib.crc32(ник.encode())`, а не
  встроенный `hash()` — тот солёный для str и меняется между запусками.
- `scale_mob` прокидывает поле `cooldown` без скейла — забудешь
  прокинуть, и КД моба потеряется (сбросится на дефолт датакласса) при
  скейле на дверях.
- В FIGHT `time_left = 0`, и `update_timer` не зовётся — иначе
  републикации таймера замораживаются на нуле (и в FIGHT таймера на
  оверлее по дизайну нет).
- `cd_left` в снапшоте заморожен между событийными публикациями —
  клиентскому ресинку нельзя верить безусловно: без `fresh_snapshot()`
  (экстраполяция к моменту отдачи `/state.json`) любой пороговый ресинк
  на странице щёлкает отсчёт колец КД назад с периодом порога. Клиент
  при этом всё равно мягкий: жёсткий снап только при расхождении > 1.2 с,
  сброс кольца — на событии атаки юнита.
- Команды голосований пересекаются между фазами (двери `1..3`, магазин
  `0..N`, прокачка `1..5`) — маппинг слов строго из текущей фазы,
  никакой глобальной таблицы команд; слово прошлого раунда валидатор
  нового отклонит. Команда отряда `бой` — вне голосований: в бою
  голосования нет, конфликта с алиасами нет (и слова `бой` нет в пуле
  `streamkit/votewords.toml`).
- Раздача слов (`_assign_words`) — ДО `ui.show_*` фазы: иначе первый
  снапшот уйдёт без слов, а структурная подпись страницы не изменится и
  DOM не пересоберётся. По той же причине `word` входит во все
  структурные подписи overlay.html — новое голосование с тем же составом
  получает новые слова. Исключение — овертайм:
  он слова НЕ перевыдаёт (снапшот меняется только флагом `overtime` и
  таймером, DOM пересборки не требуется).
- Оверлей: сентинел сброса структурных подписей — `null`, а не `""`:
  пустая структура (магазин без доступных товаров → `sig` от пустого
  списка) совпадает с `""` и пересборка DOM пропускается — на экране
  остаются строки прошлого магазина со старыми голосами (баг «выбор
  из первого магазина сохраняется во втором», когда герой потратил всё
  золото).
- Порт оверлея занят → `OverlayServer` падает с `RuntimeError` и
  подсказкой сменить `overlay_port` в config.toml (как у истории).
- Русские строки в консоли Windows могут печататься кракозябрами (cp866) —
  это только отображение консоли, не данные. Эмодзи иконок мобов/предметов
  консоль cp1251 не печатает вообще (`UnicodeEncodeError`) — CLI пулов
  переводит stdout в `errors="replace"`.
- В TOML запятая после значения — синтаксическая ошибка; при ручном
  редактировании контента прогонять `py -m apps.mini_rpg.core`.
- `prefixes.toml` нельзя класть внутрь `mobs/` или `items/` — discover_*
  поднимет его как моба/предмет и уронит игру в экран ошибки. Файл лежит
  рядом с пакетом.
- Боевая кличка присваивается мобу до создания `Combat` (`replace(mob,
  name=...)` в `enter_combat`): `Combat.__init__` копирует моба через
  `scale_mob`, поэтому переименовывать надо до, а не после.

## Portable-сборка

Не планируется. Когда понадобится — по образцу `packaging/` истории:
пользовательские файлы (`config.toml`, `.env`, `mobs/`, `items/`) рядом с
exe, пути только через `streamkit/paths.py`.

## Верификация

- Агент: `py -m unittest discover` (все тесты репо), `py -m
  apps.mini_rpg.core` (пулы валидны), compileall/импорты, `py -m
  apps.mini_rpg --smoke` (20 с на мок-чате, exit 0). Бой и экономика
  покрыты юнит-тестами на чистой модели с фиксированным seed.
- Пользователь: `py -m apps.mini_rpg` (mock_chat — эмуляция) → открыть
  напечатанный адрес в браузере, прогнать все состояния; затем источник
  «Браузер» в OBS поверх камеры.

# Мини-RPG — DEVELOPMENT

Контракты модулей, грабли, как развивать. Общие правила репо — в корневом
AGENTS.md (тесты `py -m unittest discover`, агент не запускает UI).

Статус: реализовано — все этапы PLAN.md пройдены, история реализации и
отклонения от первоначального плана — в строках «факт» PLAN.md. Правила
игры и форматы контента — в DESIGN.md.

## Модули

- `core/hero.py` — чистая модель (без IO): `Hero` (статы, уровень, опыт,
  золото, HP/мана, 3 слота снаряжения), фабрика `new_hero(base_hp)` со
  стартовыми «Кулаками» 1–2. Формулы урона/HP/маны/крита — здесь же,
  константами (`HP_PER_ENDURANCE`, `MANA_PER_INTELLECT`, `CRIT_PER_LUCK`,
  `CRIT_MULTIPLIER`, `XP_PER_LEVEL`), одно место для баланса; rng
  передаётся аргументом в `roll_damage(slot, rng)`.
- `core/content.py` — загрузка пулов: `load_mob(path)`, `load_item(path)`,
  `discover_mobs(dir)`, `discover_items(dir)`, `load_mobs/load_items`,
  `ContentError`. Валидация при загрузке (обязательные поля,
  `damage_max >= damage_min`, корректный `slot`) — битый файл роняет игру
  в экран ошибки с понятным сообщением, как в истории.
- `core/combat.py` — `Combat(hero, mob, rng)`: автомат одного боя,
  `hero_turn(weapon, direction)` / `hero_skip()` / `mob_turn(defense|None)`
  → `TurnResult`; `rewards` (скейл), `finished`, `hero_won`. Ничего не
  знает про чат и время — цикл и таймеры крутит `game.py`. Моб скейлится
  при создании (`scale_mob`): hp/урон/награды ×(1 + 0.15×(уровень героя
  − 1)), округление — `int(x·k + 0.5)` (до ближайшего целого, половины
  вверх; на границах вида x·k = y.5 возможен float-артефакт вниз, это
  норма). `Game` скейлит моба уже при броске дверей и передаёт в бой
  готового (`level_scale=0`), чтобы threat на двери совпадал с боем. Направления — англ. константы `DIRECTIONS = ("head", "body",
  "legs")`.
- `core/choices.py` — валидаторы команд под фазы: двери `1..3`, атака
  `1..6` (с отсечением `4..6` без дальнего оружия), защита `1..3`,
  прокачка `1..5`, магазин `0..n` (неподъёмные цены отсечены до
  построения списка — валидатор знает только показанные позиции).
  Подключаются к `streamkit.VoteLoop` через `validate=`. Маппинги цифр:
  `attack_choice` → (weapon, direction), `defense_choice` → direction,
  `levelup_choice` → STATS[i].
- `core/__main__.py` — CLI-проверка пулов: `py -m apps.mini_rpg.core
  [mobs_dir [items_dir]]`, exit 1 при ошибках/пустом пуле; stdout в
  `errors="replace"` — консоль cp1251 не печатает эмодзи иконок.
- `config.py` — `@dataclass Config` + `load_config()` (streamkit
  `load_toml_config`; неизвестные ключи TOML игнорируются).
- `game.py` — `Game(cfg, ui=None, mobs_dir=..., items_dir=...)`: автомат
  RUN_START (транзитный — конструктор сразу входит в EVENT) / EVENT /
  COMBAT (подфазы attack/defense/outcome/end) / SHOP / REST / LEVELUP /
  GAME_OVER / ERROR (пулы битые/пусты). Единая точка входа чата
  `handle_chat_message(user, text)`. Чистый Python: главный цикл в
  `main.py` зовёт `game.update(dt)`. Дверь — `@dataclass Door(kind, mob)`
  с иконкой/именем (у моба — его, у магазина/отдыха — свои из DOOR_VIEW);
  моб-дверь уже отскейлена под уровень героя (`scale_mob` при броске
  дверей).
  Шов оверлея — интерфейс `NullUI` (show_*/update_votes/update_timer),
  реализация — `webui.WebUI`.
- `webui.py` — `WebUI(game)`: модель состояния оверлея (чистый Python,
  без сети), атомарная публикация снапшота (deepcopy + своп ссылки), как
  в `interactive_story/webui.py`. Читает Game при публикации (панель
  героя, таймер, подфаза и HP моба в бою); конструктор зовёт `refresh()`,
  восстанавливающий снапшот из текущего состояния Game — Game входит в
  первую фазу ещё до подключения UI. Подписи команд/стат/направлений —
  словари STAT_NAMES/STAT_HINTS/STAT_GEN/DIRECTION_NAMES/DIRECTION_ACC/
  WEAPON_NAMES/SLOT_NAMES/SHORT_SLOT_NAMES, в снапшот попадают готовыми
  строками: у дверей-мобов — `threat` («HP 4 · урон 2–3»), у моба в бою —
  диапазон урона, у команд атаки — иконка/название оружия и `detail`
  («урон 2–4 +3 силы · зарядов: 4»), у итога хода — название оружия и
  броня героя, у товаров магазина — `slot_name`/`detail`/`current`
  (сравнение с экипированным). Диапазоны — через en-тире «–».
- `server.py` — `OverlayServer(ui, port, host="127.0.0.1")`:
  ThreadingHTTPServer в daemon-потоке, `/` и `/overlay.html` →
  `web/overlay.html` (путь рядом с пакетом), `/state.json` → снапшот
  (JSON utf-8, no-store), прочее → 404, логи запросов заглушены.
  Скопирован подход истории; в streamkit не выносится: файл не идентичен
  (у истории frozen-ветка путей, у mini_rpg её нет), а общий сервер
  появится только с реальным вторым идентичным клиентом.
- `web/overlay.html` — самодостаточная страница (CSS+JS inline, Rubik
  с фолбэком system-ui/sans-serif, опрос `/state.json` каждые 200 мс)
  в «комикс»-стиле по макету `designs/comic.html` (бумажные карточки,
  жирная чёрная обводка, твёрдые тени; служебные элементы макета —
  devbar, превью OBS, заглушка камеры — в прод не переносятся): слева
  постоянная панель героя (прозрачная рамка аватарки — под неё в OBS
  кладётся камера, звёздный бейдж уровня, полосы HP/маны/опыта, чип
  золота, стикеры-чипы статов, слоты снаряжения, статичная плашка
  «как играть» — управление цифрами в чате), справа экраны фаз
  (двери, карточка моба + команды + итог хода, прокачка, магазин,
  отдых, итог забега, ошибка). DOM пересобирается только по структурным
  подписям (голоса/HP/таймер — точечно). Python про пиксели ничего не
  знает.
- `main.py` — entry point: конфиг → `Game(cfg)` → `WebUI(game)` →
  `game.ui = ui` → чат → `OverlayServer` → цикл на `time.monotonic` ~60 Гц
  (`chat.update(dt)` + `game.update(dt)`), `server.stop()` в finally.
  Чат создаётся здесь, а не внутри Game (отличие от истории): `MockChat`
  при `cfg.mock_chat`/`--mock`/`--smoke`, иначе `TwitchChat` на
  `cfg.channel`. У мок-чата свой rng (`random.Random(cfg.seed)`), чтобы
  трафик чата не сдвигал броски игры. `--smoke` — авто-выход через 20 с,
  всегда мок-чат (живой Twitch не трогает).

## Игровой цикл — точные правила

- Весь тайминг через `dt` в `Game.update(dt)`; никаких sleep/потоков в
  игровой логике.
- `VoteLoop` создаётся заново на каждую фазу голосования: у дверей, атаки,
  защиты, прокачки и магазина свои валидаторы (число вариантов разное).
- Таймеры единые по фазе, как в истории: `time_left` тикает в `Game`,
  голосование закрывается явным `vote_loop.finish()` при `time_left <= 0`.
  Таймер на оверлей: `Game.update()` пушит `ui.update_timer()` каждый
  кадр, WebUI републикует снапшот только при смене показываемой секунды
  (дедупликация, как set_header у истории).
- «Нет голосов» по-разному: на выборе двери и прокачке — перезапуск
  голосования с тем же составом (игра ждёт); в бою — пропуск хода (атака
  без удара / защита без блока), бой не встаёт; в магазине — выход без
  покупки.
- Итог каждого хода боя (удар/блок, цифры урона) показывается паузой
  `combat_outcome_pause` (подфаза outcome) до открытия следующего
  голосования — иначе результат мгновенно сменится новой фазой.
- Конец выигранного боя — подфаза `end` внутри COMBAT (`combat_end_pause`,
  state остаётся COMBAT): награды и прокачки уже отыграны, оверлей
  показывает «Победа!». До UI подфаза `end` доходит без вызова ui:
  подфаза и HP моба синкаются из Game в `WebUI._publish()`.
- Пулы `mobs/` и `items/` перечитываются при каждом входе в EVENT —
  состав меняется без рестарта игры.
- Набор дверей — по правилу из DESIGN.md «Типы событий»: сначала подтип
  каждой двери (моб с шансом `MOB_CHANCE` = 70%, иначе интерактив —
  случайный из зоны отдыха и магазина, магазин только если пул предметов
  не пуст), потом мобы без повторов в тройке (при нехватке пула — добор
  с повторами). Пустой пул предметов — не ошибка: магазин просто не
  выпадает на дверях (битый файл предмета — экран ошибки, как у мобов).
- Покупка в магазине экипирует копию предмета (`dataclasses.replace`):
  `Hero.use_ranged()` мутирует `uses`, шарить Item пула с героем нельзя.
- Пауза после закрытия магазина и после отдыха — `combat_end_pause`
  (свои поля в конфиг не добавляем, пока хватает одной).
- Смерть героя → экран итогов (уровень, убито, заработано золота) →
  автоматический новый забег; цикл бесконечный, стриму не нужен рестарт.

## Оверлей (OBS Browser Source)

Окна нет: страница `http://127.0.0.1:<overlay_port>`, стример добавляет её
в OBS источником «Браузер», прозрачность нативная. Рамка аватарки — просто
прозрачная область в вёрстке с рамкой по краю; игра ничего в неё не рисует,
камера стримера — отдельный источник под оверлеем в OBS.

Фазы снапшота: `event` (3 двери с голосами), `combat` (герой/моб,
HP-полосы, текущий ход и варианты команд, итог хода), `levelup` (5 статов
с голосами), `shop` (товары с ценами и голосами, `0` — выход), `rest`,
`game_over` (итоги забега), `error` (пулы контента битые/пусты).

## Грабли

- Атомарная публикация снапшота (`deepcopy` + своп ссылки) — мутировать
  состояние мимо публикации нельзя, страница не увидит изменений.
- `VoteLoop.update(dt)` может вызвать коллбэк, меняющий фазу и обнуляющий
  `game.vote_loop` — после `update()` обращаться к нему только под
  проверкой состояния и `is not None`. Поэтому раунд закрывается явным
  `finish()` из `Game.update()`, а не по внутреннему таймеру VoteLoop.
- Бой: выбор блока моба должен делаться до подсчёта голосов чата и не
  показываться чату до результата — иначе «тайного» выбора нет.
- Команды атаки `1..6` пересекаются с командами защиты `1..3` и дверей
  `1..3` — валидатор строго из текущей фазы, никакой глобальной таблицы
  команд.
- Оверлей: сентинел сброса структурных подписей — `null`, а не `""`:
  пустая структура (магазин без доступных товаров → `sig` от пустого
  списка) совпадает с `""` и пересборка DOM пропускается — на экране
  остаются строки прошлого магазина со старыми голосами (баг «выбор
  из первого магазина сохраняется во втором», когда герой потратил всё
  золото).
- Порт оверлея занят → `OverlayServer` падает с `RuntimeError` и
  подсказкой сменить `overlay_port` в config.toml (как у истории).
- Русские строки в консоли Windows могут печататься кракозябрами (cp866) —
  это только отображение консоли, не данные. Эмодзи иконок мобов/предметов
  консоль cp1251 не печатает вообще (`UnicodeEncodeError`) — CLI пулов
  переводит stdout в `errors="replace"`.
- В TOML запятая после значения — синтаксическая ошибка; при ручном
  редактировании контента прогонять `py -m apps.mini_rpg.core`.

## Portable-сборка

Не планируется. Когда понадобится — по образцу `packaging/` истории:
пользовательские файлы (`config.toml`, `.env`, `mobs/`, `items/`) рядом с
exe, пути только через `streamkit/paths.py`.

## Верификация

- Агент: `py -m unittest discover` (все тесты репо), `py -m
  apps.mini_rpg.core` (пулы валидны), compileall/импорты, `py -m
  apps.mini_rpg --smoke` (20 с на мок-чате, exit 0). Бой и экономика
  покрыты юнит-тестами на чистой модели с фиксированным seed.
- Пользователь: `py -m apps.mini_rpg` (mock_chat — эмуляция) → открыть
  напечатанный адрес в браузере, прогнать все состояния; затем источник
  «Браузер» в OBS поверх камеры.

# ТЗ на дизайн HTML-оверлея «Интерактивная история»

## 1. Назначение

Оверлей для прямой трансляции (Twitch): зрители голосуют в чате цифрами,
а на экране стрима отображается ход коллективного прохождения текстовой
истории. Оверлей — веб-страница, которая добавляется в OBS источником
«Браузер» (Browser Source) и опрашивает локальное состояние игры
(`/state.json`) несколько раз в секунду.

Задача дизайна — макет всех экранов и состояний оверлея. Этот документ
описывает только **состав блоков и отображаемую информацию**; цвета,
шрифты, отступы и прочая стилистика — на усмотрение дизайнера.

## 2. Технический контекст

- Страница живёт поверх картинки стрима: фон страницы прозрачный,
  видны только элементы оверлея.
- Размер области задаётся стримером в OBS; макет должен масштабироваться
  без поломки в диапазоне примерно от 600×800 до 1100×1400 (портретная
  ориентация, ширина < высоты), без полос прокрутки.
- Контент целиком на русском языке.
- Интерактивности нет: ничего не нажимается, страница только отображает
  состояние, приходящее из игры.
- Обновления состояния приходят до нескольких раз в секунду; смена
  значений (счётчики голосов, таймер) не должна «дёргать» макет —
  изменения чисел и подсветок происходят на месте.

## 3. Общая структура (все экраны)

### 3.1. Шапка (видна всегда)

Единственный элемент, присутствующий на всех экранах без исключений.
Одна строка текста, состав зависит от фазы игры:

- выбор истории: `Выбор истории · <секунды>`;
- ход: `«<Название истории>» · Ход <N> · <секунды>`;
- сон между ходами: `«<Название истории>» · Ход <N+1> · <секунды>`
  (номер следующего хода и отсчёт до него);
- выбранный вариант (пауза перед сном): `«<Название>» · Ход <N> · <секунды>`;
- концовка: `«<Название истории>» · Финал · <секунды>`.

Секунды обновляются ежесекундно. Шапка — единственный «якорь», по которому
зритель всегда понимает, что игра жива и сколько осталось до события.

## 4. Экраны (фазы игры)

В каждый момент времени виден ровно один из экранов 4.1–4.4 плюс шапка.

### 4.1. Экран выбора истории

Показывается, когда чат выбирает, какую историю проходить.

- **Заголовок-подсказка**: «Выберите историю — пишите цифру в чат».
- **Список историй** (1–9 позиций), каждая позиция содержит:
  - порядковый номер (именно эту цифру зритель пишет в чат);
  - название истории;
  - короткую аннотацию (1–2 строки, может отсутствовать);
  - счётчик голосов (появляется только когда за позицию есть голоса).
- Состояния позиции: без голосов / есть голоса (лёгкая зеленоватая
  подсветка) / лидер голосования (подсветка ярче, тоже зелёная).
  Лидер должен быть визуально отличим, чтобы чат видел, «кто выигрывает».

### 4.2. Экран хода (основной экран игры)

- **Текст сцены**: связный абзац (обычно 2–5 строк после переносов,
  возможны и более длинные). Появляется первым, отдельно от вариантов.
- **Список вариантов действий** (1–9 позиций) появляется сразу вместе
  с текстом сцены. Каждый вариант содержит:
  - порядковый номер (цифра для голосования);
  - текст варианта (обычно 1 строка, возможен перенос на 2–3);
  - счётчик голосов (только при наличии голосов).
- Состояния варианта:
  - без голосов;
  - есть голоса (лёгкая зеленоватая подсветка);
  - лидер голосования (подсветка ярче, тоже зелёная; обновляется в
    реальном времени);
  - **выбранный** — после закрытия голосования победивший вариант
    подсвечивается ещё ярче (насыщенный зелёный), остальные остаются
    на экране без изменений (несколько секунд паузы до перехода в сон).

### 4.3. Экран сна (между ходами)

Контент хода скрыт; остаются только:

- шапка (с номером следующего хода и таймером до него);
- **текст итога**: последствия выбранного на прошлом ходу варианта
  (1–3 строки). Виден всё время сна (десятки секунд).

Экран намеренно почти пустой — в этой фазе на стриме идёт другой контент,
оверлей не должен отвлекать.

### 4.4. Экран концовки

Финал истории, показывается несколько секунд, затем игра возвращается
к выбору истории.

- **Заголовок**: «КОНЕЦ» или «КОНЕЦ — <название концовки>».
- **Финальный текст** (несколько строк).

Экран может занимать всю область оверлея (это единственный экран, где
допустимо перекрывать всё — момент кульминации).

### 4.5. Экран ошибки (редкий служебный случай)

Если пул историй пуст или содержит ошибку, игра не стартует и показывает
только текстовое сообщение об ошибке. Оформление минимальное, но сообщение
должно читаться.

## 5. Правила и граничные случаи для вёрстки

- Число позиций в списках — от 1 до 9; макет не должен ломаться ни при
  одном варианте, ни при девяти многострочных.
- Тексты заранее неизвестной длины (истории пишут авторы): переносы по
  словам, без обрезания и без «...».
- Счётчики голосов растут по мере голосования; под разумное число знаков
  (десятки, потенциально сотни) должно хватать места без сдвига текста
  варианта.
- Если история в пуле одна, экран выбора (4.1) не показывается вовсе —
  игра сразу начинает ход.
- Раунд может завершиться без единого голоса: тогда тот же ход
  повторяется заново (экран хода перерисовывается тем же содержимым) —
  это штатная ситуация, не ошибка.
- Шапка видна даже на экране сна и концовки.
- Переходы между экранами мгновенные по данным, но желательны плавные
  появления/исчезновения блоков (на усмотрение дизайнера).

## 6. Что передаёт игра (контракт данных)

Страница получает JSON примерно такого вида (точный формат —
`apps/interactive_story/webui.py`, примеры — `tests/test_webui.py`):

- `phase`: `select` | `move` | `sleep` | `end` | `error`;
- `header`: строка шапки (уже собранная, с таймером);
- `scene`: текст сцены;
- `options`: список `{n, label, votes, state}`, где
  `state`: `idle` | `active` | `leader` | `chosen`;
- `result`: текст итога для экрана сна;
- `ending`: `{label, text}` для экрана концовки;
- `select`: `{title, message, items}` — заголовок, текст ошибки и
  список историй (та же структура `{n, label, votes, state}`).

## 7. Результат работы

- HTML/CSS/JS-макет (можно статичный, с заглушками данных) всех экранов
  и состояний из разделов 3–5, или макет в графическом редакторе +
  передача стилей для внедрения в существующую страницу
  `apps/interactive_story/web/overlay.html`.

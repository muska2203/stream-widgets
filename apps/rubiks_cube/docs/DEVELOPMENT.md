# Руководство для разработчика (handoff)

Технические детали реализации, контракты между модулями и грабли, о которых
нужно знать перед изменением кода. Концепция и игровые правила — в
[DESIGN.md](DESIGN.md). Конкретные секреты/значения здесь не хранятся.

## 1. Окружение

- Windows, интерпретатор вызывается через `py` (Python 3.14). Команда
  `python` в PATH — заглушка Windows Store, не использовать.
- Установка зависимостей: `py -m pip install -r requirements.txt`.
- Тесты: `py -m unittest discover` из корня репо (unittest, pytest-совместимо,
  зависимостей не требует) — находит тесты библиотеки и всех приложений.
- Запуск: `py -m apps.rubiks_cube` из корня репо; авто-закрытие для проверки:
  `py -m apps.rubiks_cube --smoke`.
- Библиотеки: Ursina 8.x (Panda3D под низом), TwitchIO 2.x (`<3` — в 3.x
  другой API вокруг EventSub, IRC-клиент убран/изменён).

## 2. Карта модулей и контракты

```
streamkit/          переиспользуемая библиотека (pip-пакет, pyproject.toml).
                    Ядро без тяжёлых зависимостей: chat (Twitch IRC + мок,
                    callback-интерфейс), voting (VotingRound + VoteLoop),
                    config (TOML-загрузчик + парсер .env). Ursina-часть —
                    streamkit/overlay/ (окно-хромакей, crisp-шейдеры,
                    WindowManipulator, hex_color), импортируется только явно.
apps/rubiks_cube/   это приложение: game (автомат), cube_view (рендер),
                    ui, config, main; core/ — чистая модель куба без
                    графики и IO — покрыта тестами
    tests/          юнит-тесты приложения (тесты streamkit — в streamkit/tests/)
    tools/          offscreen-проверки скриншотами (render_check, ui_check)
    config.toml     конфиг приложения (путь — относительно config.py)
```

**Ключевые контракты (не нарушать):**

1. `Game.handle_chat_message(user, text)` — единая точка входа команд из чата.
   Источник чата (мок или Twitch) получает её как callback
   `on_message(user, text)` в конструкторе и обязан иметь метод `update(dt)`,
   вызываемый каждый кадр из игрового цикла.
2. Протокол анимации хода: сначала `cube.apply(move)` (модель уже post-move),
   затем `view.animate_move(move, on_done=...)`. `animate_move` отбирает
   entities по их ТЕКУЩЕЙ физической ячейке (`e.cell`), крутит pivot и в конце
   вызывает `sync()`, который раскладывает наклейки строго по модели.
   `sync()` — единственный источник истины для финального кадра.
   Для whole-cube ходов (`w*`) `move_info` отдаёт axis=None — ось восстанавливается
   из буквы хода (wu/wd → x, wr/wl → y), крутятся все entities.
3. `streamkit.VotingRound` не знает о чате и UI: `vote()` валидирует через
   переданный в конструктор `validate(text) -> canonical` (игра передаёт
   `core.normalize`; дефолт — любой непустой текст), невалидное
   сообщение — не голос. Ничья решается случайным выбором среди лидеров в
   `winner(rng)`. `streamkit.VoteLoop` добавляет таймер раунда: тикает от
   `update(dt)`, по истечении деактивируется и зовёт
   `on_round_end(winner|None, counts, n_voters)`; новый раунд открывается
   явным `start()`, досрочное завершение — `finish()`.
4. Конфиг приложения — `apps/rubiks_cube/config.py::Config` (dataclass) +
   `apps/rubiks_cube/config.toml` (путь по умолчанию — относительно config.py);
   загрузка — обобщённая `streamkit.load_toml_config(cls, path)`: неизвестные
   ключи TOML игнорируются, отсутствующий файл = дефолты. Секреты — только
   `.env` в корне репо (в `.gitignore`), парсер `streamkit.load_env`
   переносит UTF-8 BOM и cp1251 (Windows-редакторы) и срезает кавычки
   вокруг значений.

## 3. Модель куба (core/)

- Координаты: x = вправо, y = вверх, z = к зрителю (грань F). Каждая наклейка
  — (позиция кубика, нормаль). Ход = поворот слоя на 90° вокруг оси x или y;
  повороты всего куба (`w*`) — тот же механизм на всех слоях.
- Семантика команд: `u/d` — столбцы (нумерация слева направо от фронта),
  `l/r` — строки (сверху вниз), `w*` — весь куб. `u` = фронт идёт вверх,
  `r` = фронт идёт вправо. Циклы: `u: F→U→B→D→F`, `r: F→R→B→L→F`.
- Раскладка граней (view conventions) описана в docstring `cube.py` — она же
  задаёт маппинг на экран. Менять её = перепроверять все визуальные тесты.
- Публичное API: `Cube` (apply / apply_sequence / is_solved / scramble /
  copy), `VALID_MOVES` (16), `normalize`, `inverse`, `move_info` (ось, слой,
  направление для рендера), `sticker_transform` (позиция+нормаль наклейки).
- `scramble` не ставит ход-инверсию предыдущего; перемешка тем же набором
  команд, что доступен зрителям, — гарантия собираемости.
- CLI-проверка: `py -m apps.rubiks_cube.core [count] [seed]` печатает развёртку.

## 4. Рендер (cube_view.py) — калибровочные факты Ursina/Panda3D

Это эмпирика, проверенная скриншотами; при смене версии движка перепроверить:

- Рендер-координаты зеркалят модель по z: render (x, y, z) = model (x, y, -z).
- Направления поворотов Entity: `rotation_x=+90` выводит грань D к камере,
  `rotation_x=-90` — U, `rotation_y=+90` — R. Таблица `_ANGLES` в cube_view
  откалибрована под это; направления анимаций проверяются средним кадром.
- Наклон камеры — конфиг `cube_tilt_x/cube_tilt_y`; ориентиры: (0,0) — фронт
  анфас, (-90,0) — вид сверху, (0,90) — вид справа.
- Наклейки — двусторонние квады (`double_sided=True`), важна только
  ориентация плоскости, не сторона. Наклейки используют общую процедурную
  PIL-текстуру (`_sticker_texture`): белая заливка со скруглением + тёмное
  кольцо-бордер; entity color тонирует её мультипликативно (белое берёт цвет
  наклейки, чёрное кольцо остаётся тёмным). Тела кубиков — тёмные кубы
  scale 0.96 (видны в зазорах = сетка и общий бордер), наклейки scale 0.9,
  вынесены на 0.51 от центра кубика (во избежание z-fight). Внутри — тёмный
  сплошной кор scale 1.8: страхует от просвета хромакея при повороте среднего
  слоя. Больше делать нельзя — при scale 2.8 его грань почти заподлицо с
  поверхностью и при повороте слоя читается как чёрная «стена», а не прорезь.
- `color.rgb` в ursina 8 — алиас `rgba` и принимает float 0-1 (значения 0-255
  молча клампятся в белый!). Для 0-255 делить на 255 вручную — см. `hex_color`.
- UI (camera.ui): перекрытие элементов управляется z (меньше z = ближе,
  фон таймера z=0, заливка z=-0.01). Происхождение scale у Entity — центр,
  origin на это НЕ влияет: полоса таймера с «прибитым» левым краем сделана
  пересчётом scale_x + x. Кириллица в шрифте по умолчанию работает.
- Хромакей требует ЖЁСТКИХ краёв: стандартные шейдеры ursina (SDF-текст,
  unlit) выводят плавные альфа-градиенты на границах, эти полупрозрачные
  пиксели сливаются с цветом кея и дают ореол после фильтра. Поэтому текст,
  иконки команд и наклейки используют шейдеры с отсечением альфы
  (`discard` при a<0.5, вывод alpha=1) — `streamkit/overlay/crisp.py`
  (`CRISP_TEXT` для Text, `CRISP_UNLIT` для текстурированных Entity). MSAA в проекте
  выключено (в ursina закомментировано) — края геометрии и так жёсткие.
  Оверлей победы намеренно полупрозрачный (лежит над кубом, не над кеем) —
  crisp-шейдер на него НЕ вешать.
- Куб подгоняется под ширину окна: `CubeView.fit_width` масштабирует root
  так, чтобы наклонённый силуэт занял всю ширину, с кепом по свободной
  высоте (полоса [верх экрана … сетка голосов], верхний срез куба уходит
  под непрозрачную полосу таймера). Пересчёт — из `Game._fit_cube` при
  смене `window.aspect_ratio`. Грабля: `Entity.right/up/forward`
  (`scene.getRelativeVector`) ВКЛЮЧАЮТ текущий scale entity — для
  геометрических вычислений нормализовать (`.normalized()`), иначе
  повторный fit делит на собственный масштаб. Обводка текста — 8 тёмных
  копий вокруг основной (`_OutlinedText` в ui.py).
- Скриншоты Panda3D: принимают только ОТНОСИТЕЛЬНЫЕ пути с прямыми слэшами
  (абсолютный путь/бэкслэши → молча False). Поэтому tools-скрипты делают
  chdir в свою директорию и читают результат через
  `base.win.save_screenshot(Filename("shots/x.png"))`.
- Offscreen-режим: `loadPrcFileData("", "window-type offscreen")` ДО создания
  Ursina(). Первые кадры после старта медленные — события планировать
  цепочкой с паузами ≥1 c, иначе скриншоты «съезжают» на чужое состояние.

## 5. Twitch (streamkit.chat)

- TwitchIO 2.x под Python 3.12+: `asyncio.get_event_loop()` падает без явного
  цикла — цикл создаётся внутри фонового потока ДО конструирования Client
  (`asyncio.set_event_loop(asyncio.new_event_loop())`), см. `TwitchChat._run`.
- Клиент живёт в daemon-потоке; сообщения идут через `queue.Queue` в главный
  поток (ursina-цикл не asyncio). Ошибки соединения печатаются, не падают.
- Токен: Custom Scope Token со scope `chat:read` (twitchtokengenerator.com);
  префикс `oauth:` опционален (TwitchIO нормализует). Проверка токена без
  запуска: `curl -H "Authorization: OAuth <token>"
  https://id.twitch.tv/oauth2/validate`.
- Частая ошибка: `.env` скопирован из `.env.example` без замены заглушки —
  симптом `AuthenticationError('Invalid or unauthorized Access Token')`.
  Диагностика без раскрытия секрета: сравнить длину/края значения из
  `load_env()` с ожидаемыми.
- `event_message`: игнорировать `message.echo` и `author is None`.

## 6. Игровой цикл (game.py)

- Состояния: VOTING (таймер и сбор голосов делегированы `streamkit.VoteLoop`)
  → APPLYING (анимация хода-победителя) → WIN (оверлей + `win_pause`) →
  новая перемешка.
- Нет голосов за раунд → раунд перезапускается (без хода): VoteLoop отдаёт
  `winner=None`, `Game.on_round_end` вызывает `start_round()`.
- `mock_chat = true` в конфиге подменяет Twitch на генератор случайных
  голосов (включая мусорные сообщения — заодно проверяется фильтрация).
  В тестах UI мок-чат отключается присвоением `game.chat = None`.
- Всё таймерное — на `time.dt` в `Game.update`, не на стендовых часах.

## 7. Окно и OBS

- Borderless, размер и цвет фона — из конфига; фон = хромакей, в OBS источник
  «Захват окна» + фильтр Chroma Key. Always-on-top — через Panda3D
  `WindowProperties.set_z_order(Z_top)`.
- Закрытие окна — Alt+F4 / Ctrl+C (рамки нет).
- Перемещение/ресайз мышью — `streamkit/overlay/window_manip.py::WindowManipulator`
  (создаётся в `main.py`): ЛКМ по окну таскает его, ЛКМ в полосе `EDGE_MARGIN` px у
  правого/нижнего края (или угла) меняет размер (минимум `MIN_WIDTH`×`MIN_HEIGHT`).
  Позиция курсора — в экранных координатах через Win32 `GetCursorPos`: оконные
  координаты при движении окна «замораживаются» и для драга не годятся. Изменения
  идут через `WindowProperties.set_origin/set_size` + `request_properties`.

## 8. Верификация (обязательный паттерн этого проекта)

**РЕШЕНИЕ (зафиксировано): агент НЕ запускает приложение и UI-проверки
(`py -m apps.rubiks_cube`, `tools/ui_check.py`, `tools/render_check.py`)
сам.** UI-часть проверяет пользователь: запускает приложение у себя и в
случае ошибок прикрепляет скриншоты для анализа. Агенту доступна только
«сухая» верификация: юнит-тесты (`py -m unittest discover` из корня репо),
компиляция/импорты и чтение кода.

Справочно (для пользователя): изменение геометрии/рендера/UI проверяется
скриншотами, а не на глазок — `tools/render_check.py` (состояния куба
анфас + средние кадры анимаций), `tools/ui_check.py` (голосование/ход/
победа), скриншоты в `tools/shots/`. Юнит-тесты — для чистой логики
(модель, голосование, адаптер чата без сети через `__new__` без потока).
